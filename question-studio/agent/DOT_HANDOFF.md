# Задание для Dot: завершить банк AkadilEDU

Ты продолжаешь заполнение существующего банка AkadilEDU. Работай в своём облачном окружении: ноутбук владельца не должен участвовать в выполнении. Репозиторий: `AQADIL/AkadilEDU-PRIME`, рабочий каталог внутри него: `question-studio`.

## Результат

Последовательно завершить все допустимые конечные темы (`topics/*/isLast === true`), кроме служебной темы `random`. Составлять оригинальные школьные задания подготовки к ЕНТ/ҰБТ на казахском, русском и английском. Проверять их отдельным агентом, исправлять замечания, создавать необходимые изображения и публиковать в существующую Firebase. Завершённость темы подтверждать покрытием конкретных навыков существующими опубликованными вопросами.

Используй собственные способности автора и доступных тебе фоновых агентов ChatGPT. **Не используй OpenAI API, другие платные модельные API, чужие ключи или автоматизацию веб-интерфейса ChatGPT для обхода лимитов.** Код служит для проверки данных, отрисовки и записи в Firebase. Он сам не вызывает модель. Установленный в старом заполнителе лимит расходов и его история остаются архивом; новый процесс не списывает деньги с OpenAI API. Доступные лимиты ChatGPT/Dot, подтверждения действий и расходы Firebase по-прежнему применяются.

## Подготовка облачного окружения

1. Проверь, что выполняешься в облаке, а не на подключённом ноутбуке. Используй облачную среду Codex, если она уже настроена и доступна Dot. Если её нет, подготовь доступный облачный рабочий каталог с репозиторием. Не утверждай, что локальная задача переехала в облако автоматически.
2. Клонируй репозиторий и прочитай действующие инструкции. Нужен Node.js версии не ниже указанной в `question-studio/package.json`.
3. В `question-studio` выполни `npm ci`, затем `npx playwright install --with-deps chromium` для Linux. `npm run agent -- schemas` выдаёт точные JSON-схемы.
4. Настройки бери из переменных окружения или приватного `.env.agent`; образец — `agent/.env.example`. Путь к другому приватному env-файлу можно передать через `AGENT_ENV_FILE`. Не читай и не используй старый `.env` заполнителя: он предназначен для прежнего API-режима.
5. Требуются реальные `FIREBASE_DATABASE_URL`, `FIREBASE_STORAGE_BUCKET`, `AGENT_STATE_PATH`, `AGENT_DATA_DIR`, `AGENT_RENDER_ORIGIN`, лимиты тем и время аренды из образца. `AGENT_RENDER_ORIGIN` — локальный виртуальный origin для перехвата запросов шрифтов рендерером, а не адрес публичной админки. Сервер или открытый порт для него не нужен. В облаке оставь `AGENT_BROWSER_CHANNEL` пустым, чтобы использовать установленный Chromium.
6. Доступ к Firebase: предпочитай уже предоставленные Application Default Credentials. Иначе владелец должен подключить сервисную учётную запись через защищённые секреты окружения; `GOOGLE_APPLICATION_CREDENTIALS` указывает на файл в облаке. Не проси отправить содержимое ключа в чат. Не копируй секреты в Git, промпты, публичные артефакты или сообщения. Если облачный доступ ещё не предоставлен, остановись именно на подключении доступа и сообщи, чего не хватает. Не ослабляй Firebase Rules и не делай базу публичной.
7. Выполни `npm run check`, `npm run agent -- status` и `npm run agent -- next`. Эти команды подтверждают реальный доступ. Не запускай `npm start`: это старый API-заполнитель.

## Где хранится состояние

Источники истины — реальные `topics`, `questions`, `questionsByTopic` в Firebase. План и текущая партия хранятся под `AGENT_STATE_PATH` в приватной ветке `questionAuthoring`. Для этого проекта используй уже настроенную ветку `questionAuthoring/main`, не создавай параллельный банк.

Команды автоматически получают краткосрочную блокировку записи в Firebase, обновляют её и освобождают. Если другая команда уже работает, дождись её завершения. Автор и проверяющий могут думать параллельно, но команды изменения состояния выполняются последовательно. После потери процесса повторяй ту же команду: идентификаторы партии и квитанции сохраняются. Ошибка связи не является основанием сочинять новую партию или считать публикацию успешной.

Локальные файлы JSON нужны только для передачи результатов командам. Сохраняй их в игнорируемой `.data/agent/`. Постоянное состояние процесса не зависит от этих файлов или от облачного диска. Историю старого платного API не изменяй и не сбрасывай.

## Рабочий цикл

Все команды запускаются из `question-studio`. Для каждого входного файла сначала проверь JSON по схеме команды. Названия ниже — имена реальных рабочих файлов, которые ты создаёшь из своих результатов; не заполняй их демонстрационными данными.

### 1. Получить следующий этап

`npm run agent -- next`

Команда возвращает действие, реальную тему, принятые и прочие задания этой темы, план, снимок банка и текущий промпт. Возможные действия: `plan`, `generate`, `review`, `repair`, `publish`, `audit`, `blocked`, `completed`.

### 2. Составить или уточнить план темы

При `plan` используй схему `plan` из `schemas`: `topicId`, `target`, `goals` с уникальными ID, `curriculumRole`, `curriculumCodes`, `reason`.

Команда: `npm run agent -- plan .data/agent/plan.json`

Нормы количества бери из `bounds`, а не из выдуманных одинаковых квот. Уже выбраны компактные пределы 6–16 вопросов: узким темам ближе к нижнему пределу, обычным обычно 8–12, широким больше только при реальных пробелах. Сохрани полезные старые вопросы. Если их уже больше верхней границы, не удаляй их ради числа. При исправлении качества количество может остаться тем же.

Сопоставь тему с `src/untCurriculum.ts`. Это сохранённая карта программы 2026 года; это не доказательство того, что любой придуманный вопрос соответствует экзамену. При сомнениях проверь действующую официальную спецификацию Национального центра тестирования и приведи конкретный раздел. Отличай явно перечисленный материал от необходимой школьной предпосылки. Не объявляй внепрограммную тему завершённой и не расширяй её до олимпиадной математики. Сообщи владельцу о таких темах отдельно.

### 3. Написать небольшую партию

При `generate` создай 1–5 вопросов, не превышая остаток до `target`. Прочитай `prompt` из `next` и `src/prompts.ts`. Сохрани полный текст каждого вопроса, ответы, объяснение, подсказку и схему по `stage`-схеме.

`author.agentId` — реальный идентификатор автора/задачи. В `author.model` укажи фактически используемую модель, если она известна; иначе честно напиши `model-not-exposed`. Не приписывай себе Sol, Luna или Astra без подтверждения.

Команда: `npm run agent -- stage .data/agent/batch.json`

Она проверяет структуру, школьные обозначения, длину ответов, точные дубликаты, соответствие теме и возможность отрисовки. Затем сохраняет партию в Firebase для независимого рецензирования. Успешный `stage` ещё не означает публикацию или доказанную математическую правильность.

Для исправления уже опубликованного или отклонённого вопроса укажи его реальный `replacesId` рядом с `question`. Команда запомнит снимок исходного вопроса; публикация откажется перезаписывать его, если администратор успел изменить запись. Не изменяй существующие вопросы без конкретного обнаруженного дефекта.

### 4. Независимая проверка

Передай сохранённую партию **другому фоновому агенту**. Разрешено делегировать составление, перевод и проверку; проверяющий не должен быть автором данной партии. Если отдельный агент недоступен, не подделывай независимость и не публикуй партию — сообщи об ограничении.

Проверяющий сначала решает задачу по условию и вариантам, затем сравнивает с предложенным ответом и объяснением. Проверяет единственность ответа, область допустимых значений, лишние/потерянные корни, единицы, обозначения, диаграмму, уровень, переводы и отсутствие смысловых дубликатов. Использует промпт `reviewPrompt` из `src/prompts.ts` и возвращает точную `review`-схему: `batchId`, собственный `reviewer`, `independent: true`, `verdicts.reviews` для каждого индекса.

Команда: `npm run agent -- review .data/agent/review.json`

Если есть замечания, исправь все конкретные ошибки, передай полную исправленную партию через `stage` с `supersedes` равным ID отклонённой партии и снова отправь независимому проверяющему. Не ставь все проверки в `true` ради скорости. После трёх безуспешных содержательных исправлений сообщи о проблеме; не повторяй одну и ту же попытку бесконечно.

### 5. Публикация

После принятой проверки: `npm run agent -- publish`.

Команда создаёт изображения, повторно проверяет листовую тему, защищает от конфликта записей, сохраняет вопросы и индекс темы, читает результат обратно и выдаёт квитанцию с ID вопросов. Повтор команды продолжает сохранённую партию и не создаёт вторые копии. Если запись вопроса прошла, а связь оборвалась до индекса или квитанции, повтор восстанавливает недостающий этап.

В происхождении задания записывается `external-agent`, ID партии и реальные идентификаторы автора/проверяющего. `agent-batch:` и `agent-review:` — локальные ссылки на квитанции, а не выдуманные идентификаторы OpenAI Responses API.

### 6. Завершение темы

При `audit` отдельный проверяющий сопоставляет каждую цель плана с конкретными ID опубликованных, принятых вопросов. Используй `complete`-схему и неизменённый `bankFingerprint` из свежего `next`.

Команда: `npm run agent -- complete .data/agent/completion.json`

`complete: true` допускается только при покрытии всех целей, достаточном количестве и разнообразии, отсутствии замечаний и пробелов. Одного достижения числа вопросов недостаточно. Если есть проблемы, верни `complete: false`, укажи конкретные `issues`/`missingSkills`, исправь соответствующие записи или скорректируй план в допустимых пределах. Затем повтори аудит. При изменении банка после снимка команда отклонит устаревший аудит.

После подтверждённого завершения переходи к следующей теме через `next`. Не выбирай случайные темы. `completed` означает, что нет незавершённых и отложенных допустимых тем. `blocked` означает, что работа ещё не закончена: покажи конкретные препятствия.

## Требования к вопросам

- Казахский, русский, английский: эквивалентные условия, все четыре ответа, объяснение и подсказка. Порядок вариантов и индекс правильного ответа одинаковы. Индекс — от 0 до 3.
- Используй естественный школьный язык. Казахские обозначения: ЕКОЕ, ЕҮОБ; русские: НОК, НОД. Не оставляй gcd/lcm/mod, программные функции и вузовские сокращения без необходимости. Остатки объясняй обычными словами и школьной делимостью.
- Сложность тренировочного банка приблизительно 25% лёгких, 45% средних, 30% сложных. Это пользовательская настройка банка, не официальный процент одного варианта ЕНТ. Не заставляй маленькую тему точно соответствовать процентам.
- Один короткий ответ на вариант. Желательно до 40 символов; жёсткое ограничение валидатора — 64 символа на каждом языке. Не обрезай смысл ради лимита: переформулируй вопрос.
- LaTeX и изображения допускаются только для условия. Варианты ответов, подсказки и решения — всегда простой читаемый Unicode/текст. Дроби, системы, составные основания логарифмов и сложную запись в условии оформляй в `$...$` или `$$...$$` для рендерера.
- Переведённую инструкцию ставь перед языконезависимой формулой, формулу — в конце условия. Например, фраза «решите уравнение» переводится отдельно, изображение самого уравнения используется одно. Не добавляй переведённый текст после общего формульного блока.
- Геометрические схемы желательны, когда помогают ученику; обязательны, когда без них условие неполно или неоднозначно. Простой понятный вопрос может оставаться текстом. Схема должна соответствовать координатам, данным и взаимному расположению фигур. Невидимые рёбра — пунктиром; никаких подсказок правильного ответа в рисунке.
- Используй одну общую схему для трёх языков с нейтральными буквами и числами. Отдельные картинки нужны только когда слова нельзя вынести за пределы схемы. Рендерер сам переиспользует одинаковые изображения и обрезает лишние поля.
- Ищи официальные примеры в интернете при необходимости для формата и методов. Не копируй сборники целиком. Создавай оригинальные вопросы; не выдавай их за официальные задания экзамена.
- Не генерируй десятки поверхностных вариаций заменой чисел. Каждая задача должна проверять полезный навык, типичное заблуждение или осмысленно отличающееся условие.

## Продолжение между сессиями

Работай до завершения плана в пределах доступных лимитов и разрешений. После каждой принятой партии сохраняй прогресс через команды. Если сессия или лимит заканчивается, текущая тема и партия уже должны находиться в Firebase; следующая сессия начинает с `status` и `next`.

Настрой поддерживаемое Dot продолжение фоновой задачи или сохранённое расписание в облаке с интервалом 30 минут, если такая возможность доступна. Каждое пробуждение продолжает ту же ветку Firebase и ту же задачу. Не создавай десятки копий расписания. При лимите ChatGPT ожидай разрешённого возобновления; не обходи ограничения аккаунта. Не обещай непрерывные 24/7 без лимитов: проверь фактические возможности аккаунта и сообщи об ограничениях.

Не присылай уведомления при каждом неизменившемся опросе. Сообщай о завершении группы тем, существенной ошибке, недоступном доступе, необходимом решении или окончании всего плана. Отчёт должен показывать реальные числа из `status`, количество завершённых/отложенных тем и ID последних опубликованных вопросов. Не называй количество созданных черновиков количеством опубликованных.

## Запреты

Не запускай старый платный генератор. Не добавляй OpenAI API-ключ. Не меняй правила доступа Firebase и не публикуй сервисный ключ. Не обходи подтверждения доступа. Не создавай фиктивные тестовые данные в production. Не удаляй старые вопросы ради счётчика. Не отмечай тему готовой по одному количеству. Не утверждай, что облачный процесс запущен, пока не выполнились реальные команды в облаке и не сохранён результат в Firebase.
